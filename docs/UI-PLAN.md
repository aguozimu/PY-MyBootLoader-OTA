# OTA 上位机界面规划

> 协议版本：`OTA-PROTO-1.0`  
> 规划日期：2026-11-05  
> 技术路线：Python 3 本地 Web 服务 + 原生 HTML/CSS/JavaScript + SSE + pyserial + Python.NET/WinForms 桌面控制台

## 1. 设计目标

1. 让操作人员在一个页面内完成串口连接、固件装载、设备查询、OTA 升级和故障定位。
2. 所有危险操作有明确状态、进度和二次确认，不允许在链路未就绪时启动升级。
3. 界面显示协议的真实状态，不用动画伪装进度；进度只由“已收到匹配 AckCRC 的块”推进。
4. 离线可用，不依赖 CDN；窗口宽度适配 1280 px 以上工控机，同时兼容 1024 px。
5. 所有 TX/RX 帧和业务状态写入运行日志，便于设备联调。

## 2. 信息架构

```text
┌──────────────────────────── 顶部栏 ────────────────────────────┐
│ OTA Console  | 链路状态  | COM口/波特率/刷新  | 连接/断开        │
├───────────────┬───────────────────────────┬─────────────────────┤
│ 设备状态卡     │ 固件与升级卡              │ 事务/结果卡          │
│ 运行状态       │ 文件拖放/选择             │ 当前阶段             │
│ 程序 ID        │ 目标 ID / 文件校验        │ 总进度               │
│ 页/块/错误     │ 自动补齐提示              │ 最近错误/耗时        │
├───────────────┴───────────────────────────┴─────────────────────┤
│ 页明细表：Page 0~14 | 本地 CRC | 设备 CRC | 是否写入 | 页状态     │
├─────────────────────────────────────────────────────────────────┤
│ 收发日志：全部 / TX / RX / 业务；自动滚动；清空；下载            │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1 顶部栏

- 品牌：`OTA Console`，副标题显示协议版本 `OTA-PROTO-1.0`。
- 链路状态灯：未连接（灰）、连接中（黄）、已连接（绿）、通讯异常（红）。
- 串口选择：可刷新 COM 列表；默认 115200；支持 8N1 固定参数说明。
- 按钮：连接 / 断开；连接后串口配置只读。

### 2.2 设备状态卡

- 运行状态：中文名称 + 原始十六进制值。
- 程序 ID：十进制与 `0x0000` 十六进制。
- 当前页、当前块、错误码。
- 最近一次查询时间与响应耗时。

### 2.3 固件与升级卡

- 文件拖放区，支持 `.bin`，显示文件名、字节数、页数、页码 CRC。
- 目标程序 ID：16 位，范围 `0x0001~0xFFFF`。
- 自动补齐：不足 15 KB 时以 `0xFF` 补齐，界面明确显示补齐字节数；超过 15 KB 直接拒绝。
- 升级前检查：串口已连接、文件有效、ID 有效、无升级任务。
- 按钮：开始升级（需要确认对话框）；停止/中止。
- 设备页 CRC 未查询时禁止启动升级。

### 2.4 事务/结果卡

- 阶段：待机、连接、查询 CRC、比较页、发送控制页、发送程序页、最终校验、成功、失败、已中止。
- 总进度：以总 `SetDat` 帧为基准；控制页固定 256 帧，每个待写程序页 256 帧。
- 当前事务、当前页、当前块、重试次数。
- 失败时显示错误码中文说明与建议操作。

### 2.5 页明细表

- 15 行程序页 + 1 行控制页。
- 列：页号 / 相对地址 / 本地 CRC / 设备 CRC / 决策 / 传输状态。
- 决策值：`跳过（CRC相同）`、`写入`、`待查询`。
- 状态值：等待、传输中、已确认、失败、跳过。
- 当前传输行高亮；失败行红色标记。

### 2.6 日志面板

- 分类：全部、TX、RX、业务。
- 单行内容：时间、方向、Type、Number、Data、CRC 或业务消息。
- 默认保留 1000 行，自动滚动开关。
- 用户可清空界面日志；本地运行日志继续写入文件。
- 提供“下载当前日志”按钮，使用浏览器 Blob 导出。

## 4. 交互流程

### 4.1 连接

1. 刷新串口列表并选择 COM 口。
2. 点击连接。
3. 后端打开串口，启动固定 16 字节滑窗接收线程。
4. 成功后刷新设备状态；失败则在顶部和日志区显示原因。

### 4.2 查询

- 查询 CRC：执行 `GetCRC`，收 16 帧 `SetCRC` 和 `SetEnd`，逐帧 ACK。
- 查询 ID：执行 `GetMID`，收 `SetMID` 和 `SetEnd`。
- 查询状态：执行 `GetSta`，收 `SetSta` 和 `SetEnd`。
- 查询期间互斥，禁止重复发送；任意查询失败不影响串口连接。
- GetCRC 与升级查询沿用第一版连续接收路径：事务开始时不得清空软件帧队列、待处理帧、解析器或串口缓冲；接收状态只在打开、关闭串口和用户主动重连时复位。

### 4.3 升级

1. 每次升级必须强制重新查询 `GetCRC` 和 `GetMID`，不得复用上一次查询缓存；`GetCRC` 完成后才允许发送任何 `SetDat`。
2. 计算本地 15 页 CRC；相同页保留设备 CRC，不同页填 0。
3. 构造 1 KB 控制页，计算 Page16 自身 CRC。
4. 以 256 帧 `SetDat` 发送控制页，每帧等待匹配 `AckCRC`。
5. 按页号升序发送差异页，每页 256 帧。
6. 发送 `SetEnd`，等待 ACK。
7. 接收并确认 `SetMID`、16 帧 `SetCRC`、`SetSta`、最终 `SetEnd`。
8. 校验最终目标页 CRC 与本地页 CRC 一致且状态为 `VALID_BACKUP`，才判定成功。

### 4.4 停止

- 点击停止只发送中止意图并停止后续帧；界面不得显示成功。
- 若正在等待 ACK，最多等待当前 500 ms 窗口结束。
- 记录中止页、块和状态，提示用户重新查询后断点续传。

## 5. 安全与边界

- 服务仅监听 `127.0.0.1`。
- 固件大小严格限制为 15 KB 程序区；不足补齐需用户勾选并确认。
- 目标 ID 为 0 时拒绝；控制页 CRC 在发送前本地复算。
- 查询和升级事务不得自行破坏接收窗口；仅串口打开、关闭或主动重连时重置完整接收状态。任何事务级队列清理都必须先通过真实设备连续查询验证。
- 协议层不接受一次 UART 读取直接当帧；必须用 `A5` 搜索 + CRC 校验。
- 除 `AckCRC` 外所有业务帧等待匹配 ACK；Number 和 CRC 都一致才推进。
- `AckCRC` 自身不回确认；重复帧只重发 ACK，不推进进度。
- 日志中不输出敏感信息；固件只显示文件名、大小和 CRC。

## 6. 后端接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/state` | 获取完整 UI 状态 |
| GET | `/api/events` | SSE 实时状态与日志 |
| GET | `/api/ports` | 获取串口列表 |
| POST | `/api/connect` | 打开串口 |
| POST | `/api/disconnect` | 关闭串口 |
| POST | `/api/query` | `crc` / `mid` / `status` |
| POST | `/api/upgrade` | base64 固件、目标 ID、补齐选项 |
| POST | `/api/stop` | 中止当前任务 |
| POST | `/api/clear-logs` | 清空界面内存日志 |
